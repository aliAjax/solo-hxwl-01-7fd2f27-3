# 听力门诊 · 器械消毒与校准追踪台

面向听力门诊的消毒供应追溯工作台：消毒批次登记与放行、监测不合格锁定隔离、
器械全链路追溯与一键暂停、复检按范围恢复、校准/灭菌周期/生物监测分级提醒、
交接班与审计留痕。双人并发操作安全（不重复放行、不覆盖记录）。

## 本地启动

```bash
npm install
npm run dev        # 同时启动 API(5102) 与前端(5101)
```

打开 http://localhost:5101 。右上角可切换当前操作员（王芳/李强/赵敏），
开两个浏览器窗口选不同操作员即可模拟双人同时操作。

其他命令：

```bash
npm test           # 端到端验收（71 项断言，含并发、跨日与五组反例）
npm run server     # 仅启动 API（5102，同时托管 dist/ 静态前端）
npm run build      # 构建前端到 dist/
```

数据持久化在 `data/db.json`（原子写入），刷新、重启、跨日均不丢状态；
删除该文件后重启会重新生成演示种子数据。

## 功能与规则

**批次生命周期**：登记批次（清洗机+灭菌器+操作员+器械）→ 完成灭菌周期 →
登记化学/生物监测 → 放行（器械转无菌在库，生成 7 天无菌效期）。

**锁死与隔离**：
- 生物/化学监测「不合格」→ 批次自动锁定，同批器械自动隔离，使用中器械标记召回；
- 生物监测超过 48h 未判读 → 系统自动锁定（跨日清扫，启动与每分钟执行）；
- 设备校准过期 → 该设备批次禁止放行（前端前置校验 + 服务端强制）；
- 无菌效期过期 → 器械自动转「待处理」。

**追溯与暂停**：任一器械可反查领取诊室、使用时段、所在及后续批次；
异常时一键暂停关联器械（同批次 + 同诊室时段重叠 + 同灭菌器 24h 后续批次），
恢复时必须按指定范围勾选，逐件回到暂停前状态。

**复检恢复**：锁定批次登记复检，合格时仅勾选的隔离器械恢复（效期内回无菌在库，
过期转待处理），范围外保持隔离；批次随恢复进度转「部分恢复/已恢复」。

**分级提醒**：校准过期（严重）/≤3天（警告）/≤7天（提示）；生物监测超时（严重）/
≤12h（警告）/≤24h（提示）；无菌效期过期（严重）/≤2天（警告）/≤4天（提示）；
另有批次锁定、关联暂停提醒。交接班页汇总待放行、锁定批次、活跃暂停、
未归还器械与 24h 事件，确认交接写入审计。

**并发安全**：
- 所有变更经服务端串行事务执行；事务失败自动从磁盘回滚内存（内存/页面/持久化三层一致）；
- 变更接口支持 `Idempotency-Key`：双击/重试/刷新重发/跨重启重放都返回首次结果，绝不重复执行（仅成功才存证，失败重试得到相同错误）；
- 状态机守卫：第二个放行请求收到 409「不可重复放行」；
- 修改类操作携带 `expectedVersion` 乐观锁：他人已改动则 409，不覆盖记录。

**跨状态冲突防护**：
- 器械处于「已暂停」时，所属批次的完成、监测登记、放行都不会让它离开暂停；暂停只能按指定范围解除，解除时按批次当前状态解析应恢复到的状态（批次已放行→无菌在库、批次已锁定→保持隔离）；
- 已恢复批次再次锁定时，全部受影响器械（含曾恢复的）重新隔离，使用中的器械登记为「已召回」；
- 生物监测超过 48h 判读时限后，补录「合格」与放行均被拒绝（领域守卫，不依赖定时清扫）；时限内登记的合格结果跨日放行仍然有效；
- 设备更新先完成全部校验再修改：校验失败时内存、页面、持久化数据都保持原值。

## 结构

```
server/           零依赖 Node 后端（node:http）
  store.js        JSON 持久化 + 串行事务
  domain.js       状态机、锁定隔离、追溯暂停、分级提醒、交接班
  seed.js         演示种子数据（日期相对启动时刻，提醒开箱可见）
  index.js        REST API + 静态托管
src/              React + TypeScript 前端（Vite，/api 代理到 5102）
test/acceptance.mjs  端到端验收（npm test）
```
